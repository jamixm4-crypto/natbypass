# 🔒 Полносвязная сеть WireGuard (Full-Mesh Architecture)

NatBypass решает ключевую проблему организации P2P-сетей за NAT: **как двум устройствам, находящимся за разными провайдерскими NAT (CGNAT), соединиться напрямую без аренды платного центрального сервера**.

---

## 🛠️ Как это работает под капотом:

```
┌───────────────────────────┐                         ┌───────────────────────────┐
│     Устройство 1 (ПК)     │                         │   Устройство 2 (Роутер)   │
│   Локальный: 192.168.1.5  │                         │   Локальный: 192.168.0.1  │
└─────────────┬─────────────┘                         └─────────────┬─────────────┘
              │                                                     │
       [ STUN Request ]                                      [ STUN Request ]
              │                                                     │
              ▼                                                     ▼
      [ STUN Сервер ]                                       [ STUN Сервер ]
   (Определил: 144.172.114.55:58128)                     (Определил: 95.165.22.14:41290)
              │                                                     │
              └────────────────────┬────────────────────────────────┘
                                   │
                     [ Шифрование NaCl / X25519 ]
                                   │
                                   ▼
                   ┌───────────────────────────────┐
                   │    Сигнальная сеть E2EE       │
                   │ (Telegram / MQTT / Cloudflare)│
                   └───────────────┬───────────────┘
                                   │
                 [ Обмен пирами и STUN сокетами ]
                                   │
              ┌────────────────────┴────────────────────┐
              ▼                                         ▼
   [ Устройство 1 узнало адрес:              [ Устройство 2 узнало адрес:
      95.165.22.14:41290 ]                      144.172.114.55:58128 ]
              │                                         │
              └────── Прямой WireGuard UDP P2P ─────────┘
                      (Адресация: 10.200.0.0/24)
```

1. **STUN Discovery (RFC 5389):** Каждое устройство отправляет легковесный UDP-пакет на публичные STUN серверы (Google, Cloudflare) и узнает свой точный внешний сокет (`Внешний_IP:Динамический_Порт_NAT`).
2. **E2EE Обмен через сигнальную сеть:** Устройства шифруют свои сокеты и WireGuard публичные ключи с помощью ключей **NaCl/Box** и публикуют их в канал (Telegram, MQTT или DNS).
3. **UDP Hole Punching / Direct Binding:** Зная внешний сокет соседа, каждое устройство отправляет UDP-пакеты напрямую в порт на стороне NAT соседа. NAT провайдера открывает сопоставление (mapping), и устанавливается прямой зашифрованный туннель WireGuard на максимальной скорости вашего интернет-канала!

## 📋 Таблица адресации в Mesh-сети:

| Устройство | Виртуальный IP (WireGuard) | Роль в сети |
|---|---|---|
| Главный сервер / Роутер | `10.200.0.1/24` | Маршрутизатор домашней подсети `192.168.1.0/24` |
| Рабочий ПК (Windows) | `10.200.0.2/24` | Клиент |
| Ноутбук (Linux) | `10.200.0.3/24` | Клиент |
| Смартфон (Android) | `10.200.0.10/24` | Мобильный клиент |
