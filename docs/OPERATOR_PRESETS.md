# База Знаний: Пресеты для сотовых операторов и провайдеров РФ (DPI / TSPU Bypass)

В данном руководстве собраны протестированные конфигурации и рекомендации по настройке параметров обфускации **AmneziaWG** и пробития NAT (**CGNAT / Symmetric NAT**) для ключевых операторов связи в РФ (МТС, МегаФон, Билайн, Tele2/T2, Yota, Ростелеком, Дом.ру).

---

## 📊 Сводная таблица совместимости операторов

| Оператор | Поведение CGNAT / NAT | Блокировки ТСПУ / DPI | Рекомендуемый пресет NatBypass | Рекомендуемый порт | P2P пробиваемость |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **МТС** | Symmetric NAT (PBA блоки по 64–128 портов), агрессивный conntrack timeout (~30с) | Жёсткая фильтрация стандартного WireGuard по первым байтам рукопожатия. Сброс UDP на нестандартных портах. | **`Anti-TSPU`** или **`Strict`** (Jc=4–6, S1=68, S2=84) | `443` или `123` | Прямой P2P возможен через Port Prediction (`predicted`) или через Mesh Relay / TCP ShadowTLS. |
| **МегаФон** | Symmetric NAT (рандомизированный порт), частичная поддержка IPv6 | Фильтрация по эвристике размера пакетов и сигнатур handshake. Дроп UDP при высокой интенсивности. | **`Strict`** (рандомизированные H1–H4, S1=40, S2=70) | `443` или `53` | P2P через Birthday Probing или fallback на IPv6 Pinholing. |
| **Билайн** | Port-Restricted Cone NAT (прогнозируемый sequential delta +1..+4) | Блокировка стандартного WireGuard UDP. Трафик с энтропией QUIC и DoH обычно пропускается без помех. | **`Light`** или **`Anti-TSPU`** (Jc=3–5, S1=50) | `8443` или `443` | **Высокая** (легко пробивается через STUN + Delta spraying). |
| **Tele2 / T2** | Symmetric NAT (PBA блоки портов), строгий таймаут неактивности (20–25с) | Глубокий анализ протокола (DPI). Сброс WireGuard через 2–3 минуты после установки соединения. | **`Anti-TSPU`** (динамическая ротация каждые 4 часа + Keepalive 15с) | `443` или `53` | Средняя. Рекомендуется включение опции `CoordinatorCapable` или домашний роутер как Relay. |
| **Yota** | Аналогично МегаФон (Symmetric NAT, частая смена внешнего IP при роуминге) | Блокировка UDP пакетов с фиксированными заголовками `0x01` (WireGuard init). | **`Strict`** (Jc=5, Jmin=40, Jmax=70, уникальные H1..H4) | `443` | Через IPv6 (работает стабильно) либо через Mesh TCP Relay. |
| **Ростелеком (PON)** | Full Cone или Address-Restricted Cone NAT (белые динамические IP) | Системный ТСПУ на магистралях. Блокировка UDP 51820. | **`Light`** (Jc=2–3, S1=30) | Любой случайный (например, `42180`) | **Очень высокая** (прямой P2P устанавливается за <100 мс). |
| **Дом.ру / Эр-Телеком** | Address-Restricted Cone NAT | Локальный DPI, выборочная фильтрация UDP. | **`Light`** или **`Anti-TSPU`** | `443` или `8443` | **Очень высокая**. Отлично выступает в роли узла-ретранслятора (`RelayCapable`). |

## 🛠️ Описание пресетов обфускации AmneziaWG

Вы можете переключать и кастомизировать пресеты прямо в **WebUI (порт 8080)** в разделе *«Обфускация AmneziaWG»* или в файле `config.yaml`:

### 1. Пресет `Anti-TSPU` (Рекомендуется для большинства сотовых сетей)
Оптимальный баланс между обходом цензуры и минимальным оверхедом по трафику:
```yaml
awg:
  jc: 4          # 4 мусорных пакета перед рукопожатием
  jmin: 40       # Минимальный размер мусорного пакета (байт)
  jmax: 70       # Максимальный размер мусорного пакета (байт)
  s1: 56         # Случайный паддинг пакета инициализации (Init Packet)
  s2: 80         # Случайный паддинг пакета ответа (Response Packet)
  h1: 1827364512 # Уникальный 32-битный заголовок Init
  h2: 2938475610 # Уникальный 32-битный заголовок Response
  h3: 3847561029 # Уникальный 32-битный заголовок Cookie
  h4: 4758692038 # Уникальный 32-битный заголовок Data
```

### 2. Пресет `Strict` (Для жёстких блокировок: МТС / МегаФон / мобильный интернет в поездках)
Максимальная маскировка, разбивающая сигнатурные профили DPI:
```yaml
awg:
  jc: 7
  jmin: 60
  jmax: 120
  s1: 96
  s2: 128
  # Рекомендуется нажать кнопку «Сгенерировать случайные H1–H4» в WebUI
```

### 3. Пресет `Light` (Для домашних роутеров PON и скоростных каналов)
Минимальная нагрузка на CPU слабых MIPS-роутеров (Keenetic Start/City/Air):
```yaml
awg:
  jc: 2
  jmin: 20
  jmax: 40
  s1: 32
  s2: 48
```

## 💡 Практические советы по преодолению проблем со связью

### Проблема 1: Пакеты перестают ходить через 1–2 минуты после подключения
- **Причина**: Тайм-аут таблицы трансляции CGNAT оператора (conntrack table purge).
- **Решение**: Установите параметр `keepalive_interval: 15s` в `config.yaml`. Это сохраняет NAT-сессию открытой без значительного расхода аккумулятора.

### Проблема 2: Оператор полностью блокирует UDP (DPI глушит любые UDP-пакеты)
- **Причина**: В некоторых регионах ТСПУ включает временную блокировку всего UDP-трафика.
- **Решение**: NatBypass автоматически эскалирует соединение на **Уровень 3: TCP ShadowTLS на порту 443**. Соединение маскируется под обычный защищённый HTTPS-трафик и не может быть отфильтровано по сигнатуре UDP.

### Проблема 3: Симметричный NAT с обеих сторон (Symmetric-to-Symmetric)
- **Причина**: Прямой P2P между двумя смартфонами на сотовых операторах без внешнего IP невозможен математически без предсказания портов.
- **Решение**: Добавьте в сеть домашний роутер Keenetic/OpenWrt на проводном интернете или VPS. NatBypass автоматически задействует его как прозрачный **Zero-Knowledge Mesh Relay**: трафик пойдёт на полной скорости без задержек и без необходимости ручной перенастройки.
